# Relay interface conventions

Relay is a document workspace: white surfaces, dark ink, quiet neutral grays, readable text, and clear next actions. Apply the same system to the landing page and authenticated workspace.

- **Tokens:** `app/globals.css` is authoritative. Use `background`, `card`, `sidebar`, `foreground`, `muted-foreground`, `border`, `primary`, and `destructive` tokens. Do not override the palette inside individual screens. Keep the existing neutral palette. Primary actions use dark ink; status and destructive actions are identified by explicit text. Do not introduce new accent colors.
- **Typography:** Instrument Sans for interface and documents. IBM Plex Mono 400 for short identifiers and copyable connection instructions; it is not preloaded. Workspace titles are 25–28px; document text is 15px with 28px leading. Keep the document column at 720px and the surrounding workspace at 960px. Use sentence case and concise action labels.
- **Spacing and surfaces:** Use the established 4px spacing scale. Use whitespace and subtle fills to group content. Keep borders on form controls and necessary document or list dividers; do not frame every section, icon, empty state, or review action. Reserve elevation for overlays.
- **Actions:** Use `Button` and `buttonVariants` for links styled as actions. Default primary actions are 40px, compact actions 36px, prominent CTAs 44px. Icons are 16px with a consistent gap. Coarse-pointer buttons have a 44px minimum target. Use `default` for the main next action, `outline` for secondary actions, `ghost` for contextual controls, and `destructive` for destructive operations. Use real links for navigation.
- **Forms:** Use `Input`, `Textarea`, the shared select class, and `Field`. `Field` assigns an explicit label/control association. Preserve a draft during failed saves. Disable editing controls while saving. Announce errors with `role="alert"`; never dismiss an editor on failure. Array index keys are intentional for fixed-position editable findings/scenes: those lists do not insert, delete, or reorder while editing. If that changes, introduce durable draft IDs rather than content-derived keys.
- **Dialogs:** Use `WorkspaceDialog` / the existing Base UI foundation. Supply `returnFocusRef` for externally controlled triggers. Keep focus trapping, Escape dismissal, initial field focus, and return focus. Contextual source/history dialogs reuse the same surface. Do not add another modal library.
- **Status:** Announce asynchronous results through status regions. “Live updates” refers to Convex transport. Never turn copying a prompt, a provider completion, or a retrieval result into a connection, verification, or human-approval claim.
- **Responsive behavior:** The sidebar becomes a compact header with a keyboard-operable menu below 760px. Keep content flexible with `min-width: 0`, wrapping action groups, and breakable source URLs. Inputs use 16px text on narrow screens. Avoid fixed-height documents and sticky action bars that obscure text at zoom.
- **Motion:** Short color/opacity changes only. Existing reduced-motion rules suppress transitions and animation. No entrance delay or navigation animation.
- **Performance:** Keep public content in Server Components. Workspace-only Convex, tooltip, and toast providers live in `(app)/layout.tsx`. Read research packets and stored evidence only when requested. Keep editor identity stable; compare editable claim fields rather than serializing source excerpts on every keystroke. Do not add memoization or virtualization without a measured need.

The live shell is `components/projects/project-frame.tsx`. The older sample `components/app-shell.tsx` is not mounted by the live routes and was left functionally unchanged.
